# firehpc-nvidia-fake

Fake NVIDIA tools for FireHPC emulated GPU nodes. They let GPU monitoring
tools, such as the [CEEMS](https://ceems.dev) exporter, run on cluster nodes
without real GPUs.

This project does not depend on the FireHPC library. It runs on cluster nodes
with Python >= 3.6 and has no third-party dependency.

## Programs

### `firehpc-nvidia-smi`

The subset of `nvidia-smi` used by monitoring tools:

- `-q -x` / `--query --xml-format`: XML report of the GPUs, as parsed by the
  CEEMS exporter for GPU discovery.
- `-L` / `--list-gpus`: one line per GPU with its UUID.
- No argument: a short summary table.

It is not installed as `nvidia-smi`, so it never pretends to be a real driver.
Point tools to it explicitly, for example with the CEEMS exporter option
`--collector.gpu.nvidia-smi-path=/usr/bin/firehpc-nvidia-smi`.

### `firehpc-dcgm-exporter`

A fake [NVIDIA DCGM exporter](https://github.com/NVIDIA/dcgm-exporter),
serving GPU metrics in Prometheus text format on `/metrics` (default port
`9400`). It must run as root.

GPUs allocated to Slurm jobs report activity: the exporter reads
`SLURM_JOB_GPUS` (or `SLURM_STEP_GPUS`) in the environment of the processes in
`/proc`, the same source as the CEEMS exporter. A busy GPU follows a random
walk around a workload profile drawn from the job ID. A GPU without job decays
smoothly to idle values.

Options:

- `--config PATH`: configuration file (default `/etc/firehpc/nvidia-fake.json`)
- `--listen [HOST]:PORT`: listen address (default `:9400`)
- `--flavor {legacy,4.8.4,current}`: override the flavor of the configuration
  file.

#### Flavors

DCGM 4.6 and 4.7 renamed most fields and changed some units. The flavor
selects the metric names, the host label and the driver label:

| Flavor          | Metric names                                     | Host label | Driver label                    |
|-----------------|--------------------------------------------------|------------|---------------------------------|
| `legacy`        | `DCGM_FI_DEV_GPU_UTIL` (%), `DCGM_FI_DEV_FB_USED` (MiB), `DCGM_FI_PROF_*_ACTIVE`… | `Hostname` | `DCGM_FI_DRIVER_VERSION`        |
| `4.8.4` (default) | same as legacy                                 | `hostname` | `DCGM_FI_DRIVER_VERSION`        |
| `current`       | `DCGM_FI_DEV_GPU_UTIL_RATIO`, `DCGM_FI_DEV_FB_USED_BYTES`, `DCGM_FI_PROF_*_UTIL_RATIO`… | `hostname` | `DCGM_FI_SYSTEM_DRIVER_VERSION` |

`legacy` matches dcgm-exporter before 4.8.3, and what upstream CEEMS recording
rules expect. `4.8.4` matches dcgm-exporter 4.8.3 and 4.8.4. `current` matches
dcgm-exporter 4.9.0 and later with its default counters CSV. DCGM still
resolves the deprecated names, so dcgm-exporter 4.9.0 and later with a counters
CSV that lists them, like the one recommended by CEEMS, match `4.8.4`.

The emitted metrics are the exporter default counters, plus the profiling
counters read by CEEMS recording rules (`SM_ACTIVE`, `SM_OCCUPANCY`,
`PIPE_FP*_ACTIVE`, `NVLINK_*_BYTES`, `POWER_USAGE_INSTANT`). See
[`catalog.py`](firehpc_nvidia_fake/catalog.py) for the full list.

## Configuration

Both programs read the same JSON file, generated by FireHPC `nvidia-fake`
Ansible role:

```json
{
  "driver_version": "570.86.15",
  "cuda_version": "12.8",
  "flavor": "4.8.4",
  "gpus": [
    {
      "index": 0,
      "uuid": "GPU-8a1c6a52-2f05-5c3e-a4a4-0c0f1b3b7a10",
      "pci_bus_id": "00000000:10:00.0",
      "name": "NVIDIA H100 80GB HBM3",
      "architecture": "Hopper",
      "memory_mib": 81559,
      "power_idle_w": 70,
      "power_max_w": 700
    }
  ]
}
```

GPU indexes must be `0..N-1` in order, matching the indexes of Slurm GPU GRES
on the node.

## Limitations

- MIG and vGPU are not emulated.
- GPU shards are not linked to jobs.
- Error and health metrics (XID, row remapping, PCIe replays) are always 0.

## Tests

```bash
pip install -e utils/nvidia-fake[tests]
pytest utils/nvidia-fake/tests
```

The tests use `prometheus_client` only to parse the exporter output.
